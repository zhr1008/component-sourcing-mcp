# 确定查询和选型的执行深度

执行深度由本轮所需证据和交付物决定。权限按宿主已有规则单独核对。

| 用户目标 | 默认做法 |
| --- | --- |
| “这个 C 号是什么封装”“报 100 颗单价” | 只查所问的技术字段或数量价并在正文回复。仅比较技术参数时，复用已有详情，按需补 `szlcsc_get_part(include_procurement=false)`。 |
| “对照这个料号清单补上封装和 Datasheet” | 一次运行批量查询，沿用仍适用的旧快照，文件保留全量证据，终端只取摘要。 |
| “列几颗满足条件的候选” | 一次 `szlcsc_select` 给匹配、未知和覆盖范围。覆盖确有缺口时才补系列、后缀或分页。 |
| “给 R1/R2 实际选料” | 先核设计条件，成组选型时先离线去重，只复核要采用的条目。实际交付 AD 清单时按已核对 JSON 导出。 |
| “给冻结 BOM 做资格确认”“核这个封装能否直接换板” | 按请求核工况、原厂版本、封装和脚位，库存、价格、装配和库操作按各自需求进入。 |

选型续调会继承上次的采购数量。本轮明确只筛技术条件时，在续调中加「暂时不查报价」，清除继承的数量。只需确认已选条目的现货或数量价时，直接查该条目。

## 批量同条件分组

已知 BOM 的完整硬性约束时，用 [plan_selection_groups.py](../scripts/plan_selection_groups.py) 把相同条件的位号合并成一个查询任务。将影响选型的**全部硬条件**设为键，包括必要的功率、耐压、精度、温度或资格要求。示例只展示三列，实际按输入工况选择。

```powershell
python -X utf8 scripts/plan_selection_groups.py bom.csv --key 品类 --key 阻值 --key 封装 --reference 位号 --output groups.json
```

脚本只比较键值的文本，先去首尾空白，再要求完全相同。空白和 `待核实` 的行单列，并保留其源行号。位号原样回传。每组用 `szlcsc_select` 查询一次，沿组成员回填；若安装用途或设计约束实际不同，补上相应键后重新分组。分组报告仅表达输入条件一致，候选适用性和备选料核证由对应专项处理。
