# v0.6.0 设计基线：现有 Altium 库盘点、资料补全与封装核验

## 目标

v0.6.0 面向已经存在的大量 Altium SchLib/PcbLib 集合，不重画用户现有 AD 风格 Symbol，而是建立一个可追溯、可更新的元件资料层：

1. 直接扫描本地 SchLib/PcbLib 集合并建立资产清单。
2. 从已有属性、器件名、Comment/Description、C 编号、MPN 等线索识别元件身份。
3. 通过国内 SZLCSC 补齐采购与器件属性。
4. Datasheet 是 pinout、package、尺寸、电气参数和兼容性判定的唯一权威依据。
5. SZLCSC/EasyEDA Symbol、Footprint、3D 只能作为定位和辅助证据；即使官方封装存在，也不能覆盖 Datasheet 冲突。
6. 保留用户原 SchLib Symbol 图形与 AD 风格，仅补充参数/属性；默认 preview，写回前备份。
7. 对 Symbol ↔ Footprint 对应关系给出可解释结论、证据和状态。
8. 生成可查询/可导出的库目录，记录器件属性、封装、所在 SchLib/PcbLib、资料链接和更新时间。
9. 支持增量 refresh，不需要每次重扫全部库和重新下载所有资料。

## Altium 读取方式

v0.6.0 **直接解析现有 SchLib/PcbLib 为主路径**，不把 EasyEDA 转换后的 Symbol 当作用户库来源。

项目直接依赖当前 `altium-monkey` 公共解析能力：

- `AltiumSchLib(path)` / `AltiumSchLib.get_symbol_names(...)` 读取现有 SchLib；
- Symbol 的 pins / parameters 用于本地资产盘点；
- `AltiumPcbLib.from_file(path)` 读取现有 PcbLib；
- Footprint pads / parameters 用于 pad 编号和基础几何盘点；
- Altium implementation/model 记录用于恢复 Symbol 声明的 footprint 关联。

`altium-cruncher json-dump` 可作为诊断、互操作或未来兼容适配层，但不是 v0.6.0 的主索引格式。MCP 不自行逆向实现 Altium 二进制解析器。

对于无法被当前解析器读取的历史库文件：

- 必须报告 parse error；
- 若 catalog 中已有该文件上一次成功解析的资产记录，应保留并标记 stale；
- 不得因为一次解析失败就静默删除目录中的旧元件记录；
- 也不得把 stale 记录伪装为本次新解析结果。

## 两个独立索引

### `library-index.json`

继续负责按 C 编号管理的采购/归档库：

- SZLCSC procurement identity
- classified / flat
- SchLib/PcbLib/STEP 归档
- CAD dedupe / merge / migration

### `altium-catalog.json`

负责用户已有 Altium 设计资产：

- 哪个 Symbol 在哪个 SchLib
- Symbol pins / 已有参数
- Symbol 声明了哪些 Footprint
- 哪个 Footprint 在哪个 PcbLib
- pad 编号和基础几何
- resolved C-code / MPN
- enrichment
- Datasheet verification
- property patch 状态

二者通过 C-code / MPN 关联，但不会把价格变化和 CAD 资产状态混为一体。

## 证据优先级

### Tier 1 — Datasheet（唯一判定标准）

可用于最终 PASS/FAIL：

- 制造商型号/订货型号
- pin number / pin name / pin function
- package 名称/代码
- package body dimensions
- pitch
- exposed pad
- terminal numbering
- land pattern / recommended footprint（Datasheet 明确提供时）
- absolute maximum / recommended operating / electrical characteristics

**只有带 Datasheet 页码/章节证据的核验记录才能进入最终 `verified`。**

### Tier 2 — SZLCSC 商品元数据

用于补充和索引：

- C 编号
- 品牌
- 国内分类
- 国内库存
- 小批量价格
- MOQ / 包装
- 商品链接
- Datasheet 链接
- 商城参数

若 Tier 2 与 Datasheet 冲突，以 Datasheet 为准，并记录 `source_conflict`。

### Tier 3 — EasyEDA/SZLCSC EDA 资产

只用于辅助：

- 候选 Symbol pin mapping
- 候选 Footprint pads
- STEP/3D
- 立创内部 package naming

**不能单独把本地 Symbol/Footprint 判为 verified。**

### Tier 4 — 用户现有 Altium 库

这是需要被盘点和验证的设计资产，而不是外部真值。用户 Symbol 的图形风格应保留；只有参数属性在 preview、冲突检查和备份后才允许写回。

## 身份识别规则

自动绑定必须保守：

1. 已有精确 C 编号 → `get_part(Cxxxx)`。
2. 已有 MPN → 商城结果必须存在 exact MPN；多个 exact 结果无法用 package 唯一化时返回 `ambiguous`。
3. Symbol 名称看起来就是明确 MPN 时，可用它做 exact-MPN 查询。
4. 普通 Symbol 名称、描述、模糊关键词只能产生候选，不允许静默写成确定身份。
5. 身份变化（C-code/MPN/package）使已有 Datasheet verification 进入 stale 状态；价格/库存变化不会。

## Symbol ↔ Footprint 核验原则

`verified` 至少满足：

1. 元件身份已确定到制造商 MPN；
2. 有 Datasheet；
3. Symbol pin numbers 与 Datasheet pin numbering 可比对且一致；
4. Footprint pad numbers 与 Datasheet terminal numbering 可比对且一致；
5. Symbol 声明的 footprint link 能唯一定位到本地 PcbLib footprint；
6. package body / pitch / EP / land pattern 等机械关键项已经依据 Datasheet 检查；
7. 每项机械证据包含 Datasheet 页码/章节。

Pin name 允许记录别名差异（例如 VSS/GND、IO0/GPIO0），但 pin number mismatch 是阻断项。

若 Datasheet 缺失、页码缺失或机械信息无法可靠抽取，应返回 `manual_review` / `mechanical_review_required` / `insufficient_evidence`，不能因为立创 Footprint 看起来一致就判 PASS。

## 属性补全策略

默认只生成 property plan，不直接覆盖 SchLib。可补字段包括：

- Manufacturer
- Manufacturer Part Number
- LCSC Part #
- SZLCSC Category
- Package
- Description
- Features
- Datasheet
- SZLCSC URL
- Small Batch Price CNY
- SZLCSC Stock
- MOQ
- Packaging
- `Spec: <商城参数>`（all 模式）

规则：

- 已有同值 → keep；
- 缺失 → add；
- 已有不同值 → 默认 conflict；
- 只有显式 `overwrite_existing=true` 才允许 update；
- 实际写回默认 `dry_run=true`；
- 写回前按 SchLib 备份；
- 不替换 Symbol 图形；
- 不用 EasyEDA Symbol 替换本地 Symbol；
- 不擅自改 Footprint implementation/link。

## Catalog / 表格

Catalog 每个 symbol 记录：

- asset id
- SchLib 完整路径 / 库名
- component name / aliases
- existing MPN / C-code / brand / package hints
- resolved MPN / C-code
- SchLib pin number/name/type
- linked footprint name/library
- link 状态：resolved / missing / ambiguous
- PcbLib 完整路径
- footprint pad numbers / count / 基础几何
- 品牌 / 分类 / package
- Datasheet 本地路径与 URL
- product page
- price / stock / MOQ / packaging
- 完整 SZLCSC parameters
- verification status / evidence / issues
- last checked

导出支持 JSON + Excel 友好 UTF-8-BOM CSV。CSV 用于日常查找，JSON 保留完整结构和证据。

## 更新机制

本地 CAD 与网络元数据独立更新：

- 文件使用 path + size + mtime，按需增加 SHA256 fingerprint；
- 未变化 SchLib/PcbLib 复用上次解析结果；
- 修改过的库文件才重新解析；
- 解析失败时保留 last-good record 并标 stale；
- SZLCSC 元数据独立记录 `last_checked_at`；
- refresh 按 `max_age_hours` 只刷新过期记录；
- price / stock / MOQ 等动态字段变化不触发 CAD 重画，也不使已通过的 Datasheet verification 失效；
- C-code / MPN / package identity 改变时必须重新核验；
- Datasheet 下载按 C-code 复用，避免同一器件重复下载。

## 典型工作流

```text
scan existing SchLib/PcbLib
        ↓
建立 altium-catalog.json
        ↓
exact C-code / exact MPN enrichment
        ↓
下载 Datasheet
        ↓
Agent 阅读 Datasheet + 页码证据
        ↓
Symbol pins ↔ Datasheet pins
        ↓
Footprint pads/geometry ↔ Datasheet terminals/mechanical data
        ↓
verification record
        ↓
property plan
        ↓
dry-run + backup + property apply
        ↓
重新扫描确认 AD 库可正常读取
        ↓
导出 JSON/CSV 元件目录
        ↓
以后 incremental refresh
```
